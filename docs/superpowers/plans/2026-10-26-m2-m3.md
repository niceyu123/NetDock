# NetDock M2 + M3 Implementation Plan

> Execute inline with superpowers:executing-plans. The user's explicit implementation request supplies the execution authorization.

**Goal:** Add real UDP, then complete the professional debugging workbench without regressing TCP.

**Architecture:** Keep the existing TransportService, serial network queues, generation tokens and bounded SessionTrafficStore. Add UDPService with Network.framework receiveMessage, UDP listener flows and numeric unicast endpoints. Add a single cancellable MainActor periodic sender, versioned command storage and explicit file import/export.

**Spec:** NetDock_V1_Codex_开发规格书.md sections 3–9 and M2/M3; current user requirements supersede the prior M0/M1-only scope.

## Constraints and decisions

- Native SwiftUI, macOS 14/iOS 17, no third party runtime dependencies. Preserve icon and IDE changes. No automatic commit/push.
- UDP ready means local API readiness. One receiveMessage = one datagram, never concatenate RX. Never label sources as TCP connections.
- Blank UDP client local port means automatic allocation; server port stays 1–65535. Local address can be blank (any), IPv4 or IPv6. Exclude multicast/broadcast targets.
- Mac/wide iPad retain inspector; compact layouts retain bottom send panel with a sheet for sources/advanced sends. Native sheets for commands/export.
- Use immutable payload/target snapshots for a running send loop. Pause/stop/background/failure cancel its only task. Pending network operations finish or time out before another loop sends.
- Preserve old schema-1 sessions by decoding new fields with defaults. Imported IDs are regenerated to avoid replacing active sessions. No raw traffic persisted automatically.
- UDP arbitrary-target sends must retain the listener's local port. Verify Network.framework behavior before choosing the specification's documented BSD fallback.
